# Bhavano mobile — local build & run

Expo SDK **57** (`~57.0.4`), React Native **0.86**, expo-router, **managed workflow**
(no `ios/` or `android/` in git — they're generated by `expo prebuild`). pnpm workspace;
run everything from `apps/mobile/` unless noted.

> `AGENTS.md` in this folder: Expo 57 changed a lot — check
> <https://docs.expo.dev/versions/v57.0.0/> before touching native config or upgrading a package.

---

## 1. Prerequisites

| Tool | Notes |
|---|---|
| **Node ≥ 22** | matches the repo `engines` and the EAS builder |
| **pnpm 11** | `corepack enable` (version pinned in root `package.json`) |
| **Watchman** | `brew install watchman` — Metro file watching |
| **Xcode** (iOS) | full app from the App Store, then `xcode-select --install`; open once to accept the licence |
| **CocoaPods** (iOS) | `brew install cocoapods` |
| **JDK 17** (Android) | `brew install --cask temurin@17`; set `JAVA_HOME` |
| **Android Studio** (Android) | install the **SDK Platform 35**, **Build-Tools**, **Platform-Tools**, and an **emulator** image via SDK Manager; set `ANDROID_HOME` (usually `~/Library/Android/sdk`) and add `platform-tools` + `emulator` to `PATH` |
| **fastlane** (only for `eas build --local`) | `brew install fastlane` |

A physical iOS device also needs a signing identity (the EAS-managed certs, or your own Apple
Developer account). Simulators/emulators need no signing.

## 2. First-time setup

```bash
# from the repo root
pnpm install

cd apps/mobile
cp .env.example .env      # then fill in the values below
```

`.env` (all keys are `EXPO_PUBLIC_*`, so they're inlined into the JS bundle at build time — no secrets):

| Key | Local value |
|---|---|
| `EXPO_PUBLIC_BFF_URL` | `http://localhost:4000` for the simulator; your Mac's **LAN IP** (`http://192.168.x.x:4000`) for a physical device |
| `EXPO_PUBLIC_SITE_URL` | `https://bhavano.com` (used only for legal links) |
| `EXPO_PUBLIC_GOOGLE_*_CLIENT_ID` | leave blank unless testing Google sign-in |
| `EXPO_PUBLIC_GOOGLE_MAPS_ANDROID_KEY` | leave blank; the Android map pin-picker just won't render |

Start the BFF separately (`pnpm --filter @bhavano/bff dev` from the repo root) so the app has an API.

## 3. Dev server (fastest loop — JS only)

```bash
pnpm start           # = expo start
```

Then:
- **`i`** / **`a`** — open the iOS Simulator / Android emulator (installs a **dev client** the first
  time — this project uses `expo-dev-client`, not Expo Go).
- Scan the QR with a **physical device** that has the dev-client build installed.
- **`r`** reload, **`j`** open the debugger, **`m`** dev menu.

This only reloads JS. Native changes (new native module, `app.config.js` edits, icon changes)
need a rebuild — sections 4–6.

## 4. Build + run on a simulator / emulator

Compiles the native app locally with Xcode / Gradle, installs it, and starts Metro.

```bash
# iOS  (runs `expo prebuild` for ios/, then xcodebuild)
pnpm run ios                       # Debug on the default simulator
npx expo run:ios --configuration Release
npx expo run:ios --device          # pick a booted simulator or plugged-in device

# Android  (runs `expo prebuild` for android/, then `gradlew`)
pnpm run android
npx expo run:android --variant release
npx expo run:android --device      # emulator must be running, or a device with USB debugging
```

First run is slow (pods / Gradle download). `expo prebuild` regenerates `ios/` and `android/`
from `app.config.js` each time — **don't commit them**, and re-run after any native config change.
Add `--clean` to wipe and regenerate the native dirs.

---

## 5. Physical device

1. `EXPO_PUBLIC_BFF_URL` → your Mac's LAN IP (not `localhost`), and make sure the BFF binds `0.0.0.0`.
2. **iOS**: `npx expo run:ios --device` and pick the device. Needs a provisioning profile — easiest is
   `npx eas-cli build --profile development --platform ios` once to let EAS provision it, install that
   build, then iterate with the dev server.
3. **Android**: enable USB debugging, `adb devices` to confirm, then `npx expo run:android --device`.

## 6. Reproduce an EAS build locally (`eas build --local`)

Runs the **exact** EAS pipeline on your Mac — fresh project copy, fresh `pnpm install`,
`expo prebuild`, `pod install` / Gradle, fastlane → `.ipa` / `.aab`. Use this to debug a failing
cloud build, since it reproduces the clean-install + prebuild behaviour that your dev
`node_modules` hides.

```bash
EAS_LOCAL_BUILD_SKIP_CLEANUP=1 npx eas-cli@latest build \
  --platform ios --profile production --local

EAS_LOCAL_BUILD_SKIP_CLEANUP=1 npx eas-cli@latest build \
  --platform android --profile preview --local     # preview = installable APK, no store creds
```

`SKIP_CLEANUP=1` leaves the temp build dir for inspection. Requires `fastlane` (iOS) and a full
Android SDK + JDK 17 (Android).

## 7. Native IDE workflow (deepest debugging)

```bash
npx expo prebuild --platform ios --clean

# Android

```

## 8. Debug just the JS bundle

The step that runs inside the native build and is the usual source of Metro errors:

```bash
npx expo export:embed --eager --platform ios --dev false \
  --bundle-output /tmp/main.jsbundle --assets-dest /tmp/assets
```

If this fails but `expo start` works, it's almost always a **module-resolution** problem — see
the monorepo notes below.

## 9. Cloud builds (EAS) — reference

```bash
npx eas-cli@latest login                                   # or: export EXPO_TOKEN=...
npx eas-cli@latest build --profile production --platform all --clear-cache
npx eas-cli@latest build:view <id>
npx eas-cli@latest submit --profile production --platform ios
```

Profiles (`eas.json`): **development** (dev-client, internal), **preview** (internal APK/`.ipa`,
no store), **production** (store, `autoIncrement`, `appVersionSource: remote` so EAS owns the
build number). Always pass **`--clear-cache`** after changing dependencies — EAS otherwise reuses
a cached `node_modules`. A Gradle failure citing `maven.production.caches.eas-build.internal` /
`504 Gateway Timeout` is EAS infra, not the project — just retry.

## 10. Monorepo gotchas

pnpm's strict `node_modules` doesn't hoist transitive deps, so anything the **native build
tooling** resolves from `apps/mobile/` must be a **direct dependency** here, even though it's
"really" a dep of `expo` / `react-native-reanimated`:

- **`babel-preset-expo`**, **`@babel/core`** — `babel.config.js` loads `babel-preset-expo`; Metro's
  transformer needs both. In `devDependencies`.
- **`react-native-worklets`** — required peer of `react-native-reanimated@4.x`;
  `babel-preset-expo` auto-loads `react-native-worklets/plugin`.

Symptom when one is missing: the native build dies with
`Cannot read properties of undefined (reading 'transformFile')`, and one layer down in the
decoded EAS log, `Error: Cannot find module '<name>'` inside Metro's `Transformer` constructor.
Fix = add the module to `package.json` at the version already in `pnpm-lock.yaml`, `pnpm install`.

Other notes:
- **`@bhavano/types`** ships from its compiled `dist/`, which is **committed** (normally
  gitignored) via a scoped negation in the root `.gitignore` — nothing in the mobile build runs
  `tsc` for it. Rebuild + recommit `packages/types/dist` whenever `packages/types/src` changes:
  `pnpm --filter @bhavano/types build`.
- **No `expo-updates`** currently — it was removed while stabilising the build, so the
  `updates` / `runtimeVersion` block in `app.config.js` is inert and OTA is disabled. Re-add
  deliberately (`npx expo install expo-updates`, pinned to the SDK's bundled version) on a
  known-good SDK.
- Pinned to **`expo@57.0.4` / `metro@0.84.4`** — the last set that built cleanly on EAS. Don't run
  a blind `npx expo install --fix`: on this pnpm workspace it did a *partial* upgrade that left
  two Metro toolchains side by side. If aligning the SDK, do a full lockfile regen (`pnpm dedupe`)
  and a device smoke-test.

## 11. Troubleshooting quick table

| Symptom | Fix |
|---|---|
| Metro won't start / stale cache | `npx expo start --clear` |
| `transformFile` undefined in a native build | missing direct dep — section 10 |
| `Cannot find module '@bhavano/types/...'` | `pnpm --filter @bhavano/types build` (dist must exist) |
| iOS pods out of date after a native change | `npx expo prebuild --platform ios --clean` |
| Android `SDK location not found` | set `ANDROID_HOME`, or add `sdk.dir=...` to `android/local.properties` |
| Physical device can't reach the API | `EXPO_PUBLIC_BFF_URL` = LAN IP, BFF on `0.0.0.0`, same Wi-Fi |
| EAS build: Maven `504` in Gradle phase | transient EAS infra — retry |
